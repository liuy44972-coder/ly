# 失败定位与重试

## 1. 判定顺序

远程用例失败时，**按顺序**排除，前一层成立就停在该层，不要把环境问题写成断言问题：

| 顺序 | 判定层 | 典型信号 | 处理 |
| --- | --- | --- | --- |
| 1 | 环境/网络 | DNS、超时、502/503、`API_BASE_URL` 指向错误服务、API 环境与 `MONGODB_DB` 不匹配 | 标记 `blocked`，不改断言 |
| 2 | 鉴权 | `611`、缺少账号令牌 `612`、Cookie 过期 | 重新取运行时凭据；取不到则 `blocked` |
| 3 | 前置数据 | 单据状态不符、版本门槛 `695`、一次性资源已用 `697`、等级/白名单不满足 | 标记 `blocked` 并说明需要准备什么 |
| 4 | 契约变化 | 字段增减、类型变化、错误码语义变化 | 报告冲突，等用户确认后改用例 |
| 5 | 断言写错 | 前四层都排除，实际响应与文档一致但断言写错 | 给出改前/改后建议，**等用户授权后再改** |
| 6 | 服务真实缺陷 | 文档与断言都正确，实际响应不符合契约 | 只报告缺陷，不改测试、不改生产代码 |

报告分析使用与上表对应的归因：环境/网络 + 鉴权 → 「环境或鉴权问题」，前置数据 → 「用例设计缺陷」，契约变化 → 「契约变更」，断言写错 → 「断言写错」，服务真实缺陷 → 「服务真实缺陷」，前五层都无法排除 → 「待确认」。

## 2. 常见失败分类

- 代码断言失败；
- 接口契约变化；
- 远程服务错误；
- 测试数据已消费/不存在（含「已使用」「已领取」「单据已终结」）；
- 前置数据不满足（版本门槛、等级门槛、白名单账号）；
- 鉴权失效；
- 环境或网络问题（含 API 环境与 DB 库不匹配）；
- 服务真实缺陷（同请求可稳定复现，且与文档不符）。

## 3. 重试规则

- 网络错误、超时：允许重试 **1 次**，仍失败按第 1 层处理；
- 业务码失败（断言不通过）：**禁止重试**，先定位是契约变化还是断言写错；
- 兑换码、单据、邮件等一次性资源：**永不重试**，失败后必须换资源或换账号，禁止用同一份数据反复试探；
- 重试必须记录次数与前后响应差异，不得只保留最后一次结果。

## 4. 禁止私自修改

失败原因未确认前，不得改动断言值、预期错误码、用例逻辑、`fixtures/` 数据、门控开关、jest 配置或接口路径来让结果变绿；也不得用 `test.skip`、删除用例、放宽断言、把失败标成 skipped 的方式“修复”。只能报告失败用例、判定层级和候选原因，等用户确认后再改。
