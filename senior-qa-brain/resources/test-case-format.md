- 总用例数: X 条
- 可自动化: X 条 (XX%)
- 不可自动化: X 条 (XX%)

| P2 | X | X | XX% |
| P3 | X | X | XX% |

```
### 输出规则

- 用例明细采用“一条用例一个小节”的结构，严格按照固定模板展示：分组名称、用例标题、📋 前置条件、🎬 执行步骤、✅ 预期结果、📊 用例属性。
- 用例明细前必须输出“测试统计”，包括用例概览和按优先级分布。
- 测试用例模板在用例明细结束后结束，不包含风险评估、自动化建议和待确认事项。
- 只有用户明确要求单独分析时，才在模板之外另行输出风险评估、自动化建议或待确认事项。
- 不输出状态、备注、测试环境和截图。
- UI 测试用例必须标记 Playwright UI 自动化可行性，格式严格为 `**UI自动化**: ✅ 可自动化` 或 `**UI自动化**: ❌ 不可自动化`，仅标记可行性，不添加自动化方式或详细说明
- 服务端测试用例不添加 UI 自动化字段
- 判断为“✅ 可自动化”必须同时满足：纯 Web UI 操作、有明确验证点、无第三方授权/支付/人机验证
- 存在人工主观视觉判断、第三方 OAuth、真实支付或人机验证任一情况时，标记为“❌ 不可自动化”
- 服务端测试步骤应优先使用接口请求、参数构造、响应校验、数据库/缓存/消息结果校验等可执行表述。
- 新增数值字段的测试用例必须覆盖：正常正数、0、最小值、最大值、越界值和精度值。
- 字段类型测试必须覆盖：字段缺失、null、空字符串、字符串、布尔值、数组和对象。
- 特殊字符测试必须覆盖：空格、Unicode、Emoji、HTML 和 SQL 注入字符串，并验证不会发生隐式转换或数据污染。
- 必须区分独立业务字段与新增字段，禁止将 `item` 与 `exp` 混为同一字段；同时验证 `exp` 写入、读取、持久化、旧字段兼容，以及多个接口返回值与数据源一致。
- 测试步骤控制在 1-2 个，优先合并重复操作，写成可执行的编号步骤；每个测试步骤必须有且仅有一个对应的预期结果，按步骤顺序一一对应，禁止多个步骤共用一个预期结果。
```

## 字段说明

### 用例ID命名规范
`TC-[模块缩写]-[序号]`

示例：
- TC-PROJ-001（项目管理模块第1条用例）
- TC-USER-001（用户管理模块第1条用例）

### 优先级定义

| 优先级 | 定义 | 说明 |
|--------|------|------|
| P0 | 致命级 | 核心功能不可用，阻塞后续测试 |
| P1 | 严重级 | 影响主要业务流程，用户无法完成关键操作 |
| P2 | 一般级 | 影响部分功能，用户体验不佳 |
| P3 | 轻微级 | 界面瑕疵，非关键提示信息 |

### 状态定义

| 状态 | 含义 |
|------|------|
| ✅ 实测 | 预期结果来自真实探测，已验证 |
| ⚠️ 推断 | 限于无法探测的场景，基于业务规则推断 |
| 🔄 待验证 | 尚未执行探测，待验证 |

### 备注字段
- 记录特殊情况或需要说明的内容
- 标注推断依据
- 记录已知问题或限制
